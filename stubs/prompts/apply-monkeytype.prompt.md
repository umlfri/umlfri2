# Task

Apply type information from the corresponding `.pyi` files in `stubs/monkeytype` to the existing `.pyi` stub files in `stubs/merged`.

# Inputs

- `stubs/merged` contains stubs generated by `stubgen`
- `stubs/monkeytype` contains stubs generated by `monkeytype`

# Output

- save the updated stubs back into `stubs/merged`

# Rules

1. Treat the stub in `stubs/merged` as the authoritative source of module structure.
2. Preserve all classes, `NamedTuple`s, protocols, constants, exports, imports, and members defined in the stubgen output.
3. Do not remove any public API.
4. Do not add new classes, constants, or exports that exist only in the monkeytype output.
5. Copy only more precise parameter types and return types of existing functions and methods from monkeytype.
6. Do not add new functions or methods.
7. If monkeytype provides a more specific type than stubgen, use the monkeytype type.
8. If monkeytype provides a suspiciously narrow type, prefer a safer and more general type.
9. When in doubt, keep the existing type.
10. Do not perform any formatting or normalization changes unrelated to applying monkeytype types.
11. Do not create new type aliases.
12. Do not remove existing imports.
13. Preserve the existing directory structure and file names.
14. The result must be a valid `.pyi` file compatible with Pyright.
15. Merge files manually. Do not use any automated merge tools.
